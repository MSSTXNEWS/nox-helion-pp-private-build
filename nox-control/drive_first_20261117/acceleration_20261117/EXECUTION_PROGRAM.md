## Критический путь

1. Root публикует и один раз запускает ограниченный read-only audit main HTML, реально связанных JS и наблюдаемого alias. Existing owner operator, workflow, auth и host pin сохраняются. Нет model POST, создания диалога, STOP, reload, изменения server source. Один audit должен установить served hashes, owner flag и фактическое API wiring.
2. UI исполнитель сопоставляет результат с готовым source. Если native режим уже включён — не устанавливать второй bridge. Если нет — минимальный patch к подтверждённому server binding или готовому asset; владелец соответствующего claim устанавливает его с rollback. STOP семантика определяется actual handler, а не одним именем endpoint.
3. O1 завершает свою четырёхфайловую chat/S03 правку и передаёт exact installed postimages. Root не заменяет эти пути конкурентной версией. Исторический inflight4 не сбрасывать по возрасту.
4. После authoritative installed receipt и owner admission — один новый bounded reasoning canary с условиями в текущем сообщении. Сохранить durable intent до отправки, затем сверять тот же dialog/terminal/history. Подготовленный guard требует совпадения terminal exchange с сохранённой парой. Переданная браузером history может заменяться серверной историей; межходовую память проверять только отдельным вторым запросом после подтверждённой seed-пары S03, с новым intent/admission. Повторить readback при неизвестном исходе, а не model POST.
5. Для ссылки указать отдельно: route, served UI, реальный ответ модели, S03, доступность в браузере. Cloud browser block не считать работоспособностью страницы. Отдать владельцу новый main chat адрес с точным статусом.
6. O2/O5 завершают доказательную offline adoption и NORMAL3. Root переносит подготовленные исправления cache/adviser в соответствующий existing binding только после совместимости; без второй очереди, нового независимого планировщика и скрытых model downloads.
