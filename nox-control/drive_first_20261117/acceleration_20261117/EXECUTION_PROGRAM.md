## Фактическая команда текущего сеанса

Root координирует общие изменения и нативные команды. Ровно три дочерние задачи:

1. `/root/resonance_native` — готовый основной UI, точный menu overlay и определение настоящего источника model identity.
2. `/root/dispatcher_acceleration` — substantive writer/spawner review, проверка offline cutover и защита нового разговора при остановке watchdog.
3. `/root/integrations_completion` — existing adviser completion, совместимость callback, независимые проверки и устранение конкретных дефектов диагностики.

При завершении полезной задачи root назначает следующую готовую работу через followup. Общие исходники читаются один раз по SHA; перепроверки выполняются при изменении входов или конкретном новом риске. Исторические completed результаты сохраняются. Непроверенное действие не получает статус завершённого.

## Критический путь и следующий шаг

### 1. Закончить текущую проверку launcher и собственного прерывания

Готовый единый O1 batchsource82c5053fa97b52224abe9722881c424c93fd2430 уже запущен соседним координатором: request6961965545, run44183713964/job134394515659. Повторной команды от этой команды нет.

Фактический результат: `HOLD_BEFORE_SEND`, внутренний `HOLD_PARENT_SHELL_ENTRY_UNRESOLVED`. Parent PID498567 имеет argc2; checker ожидал Bash `-c` с argc≥3. Девять закреплённых PID/start/argv/exe/cwd совпали. Шесть новых source metadata прочитаны, но capsule не выдана. HTTP login/create/model/get0; service mutations0; counter4 и его SHA4b331e0d… неизменны; temporary key detached and verified.

Следующее действие — узкая поддержка фактически закреплённого file-based Bash parent в existing observer и соответствующем caller/decryptor. Сохраняются exact process selectors, retained no-follow directory/file reads, bounded source bytes, credential-literal check, encrypted capsule и контекст AAD. После публикации проверенного изменения root сверяет намерения другой команды и отправляет единственную согласованную команду. Старый completed canary44177251374 не используется повторно. Отсутствие вывода не считается отсутствием эффекта: при UNKNOWN сначала readback.

Критерий закрытия: получены все необходимые source bodies и Supervisor bindings; наблюдаемая собственная отмена отдельно подтверждена в пределах transport/counter contract. Browser click, GPU task cancellation и exact release call count не выводятся из одного закрытия HTTP response.

### 2. Выполнить согласованный common/arbiter cutover

Шесть прежних sources из441772 прочитаны полностью,48 992B/6exactSHA. Подтверждён chat-watchdog, способный перезапускать proxy. Current O2 offline candidate уже предусматривает его остановку до proxy и восстановление после bind. Оставшийся `counter_scope` строится на содержательном разборе точных launcher bodies и текущих lifetime, а не на отсутствии строкового маркера.

Установщик сохраняет private original bytes и факт неизвестных исторических inflight4. Перед заменой он проверяет действующие источники, владельцев записи, актуальный owner idle и модельные slots; останавливает известные spawner/writer lifetimes; повторяет CAS и создаёт новую generation. Новое поколение связывается с настоящим процессом, сохраняя arrivals до bind.

Найденная гонка: владелец может начать разговор во время ожидания watchdog.stop. Узкая правка повторяет существующий owner_idle непосредственно перед proxy.stop; normal и busy ветви проходят2/2. Перед принятием требуется проверить фактический caller recovery: busy proxy нельзя остановить и через путь rollback; частично остановленный watchdog должен оставаться явно учтённым.

Критерий закрытия: реальные installed postimages, завершённые старые writer lifetimes, связанная новая generation, действующие owner/STOP guards и восстановленные штатные сервисы.

### 3. Запустить NORMAL3 на существующей очереди

Используется уже подготовленный sourcev0.4.3, GitLab420e194f. Он прошёл испытание с настоящими локальными дочерними процессами, включая ограниченное восстановление idle-пула. Это source/local evidence; native запуск остаётся следующим действием после common adoption.

Начальный режим: три resident worker и максимум два одновременно активных CPU_LIGHT задания. Общение владельца приоритетно. Фоновые model requests во время разговора запрещены действующим admission; при проверенном idle допускается лишь установленный host budget. FORSAZH6 включается отдельно после ресурсной и функциональной приёмки NORMAL3.

Критерий закрытия: три реальных PID/start/heartbeat; шесть уникальных существующих TaskID с исполненным handler, claim/fence, durable result и S03, без повторных side effects. Пустые процессы, fixture задания и расписания не заменяют эти результаты.

### 5. Закрывать остальные направления по готовности зависимостей

Существующая концепция,240карточек и пакеты памяти/обучения сохраняются. Очерёдность следующей волны: scope-safe S03 retrieval и provenance; долгий диалог с управлением контекстом; действующие adapters и обучение с quality gate/rollback; Drive-first cache/backups; затем Radio, media и остальные пользовательские функции.

Большой объём Google Drive не увеличивает физическую RAM/VRAM. Любая загрузка должна пройти фактический ресурсный admission; стартовый preload ограничивается выбранным рабочим набором. Приоритетные веса и учителя сохраняются на Drive согласно существующему правилу владельца. Размер контекста из GGUF metadata не считается проверенной рабочей длиной контекста.

## Правила ускорения в исполнении

- Независимые задачи идут параллельно; один shared native writer владеет изменением сервера.
- Достаточная адресная проверка закрывает изменение. Уже принятые неизменённые suites не запускаются заново без причины.
- Source delta публикуется согласованно с manifest и проверяется exact readback.
- Подготовленный старшим координатором запуск сначала находится в intent/receipt; повтор не отправляется.
- После каждого реального результата выбирается следующая READY задача. Если все остатки зависят от конкретного недоступного input, сохраняется точный blocker и owner; пустая эстафета не создаётся.
- Различаются SOURCE_TESTED, MERGED, INSTALLED, LOADED_OR_SERVED, USED_WITH_DURABLE_RESULT. Процент ускорения появляется только после сопоставимых измерений.
