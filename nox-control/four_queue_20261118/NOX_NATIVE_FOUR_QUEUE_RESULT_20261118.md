# NOX — результат запуска трёх процессов и четырёх очередей

Проверенное состояние: **18 ноября 2026, 00:18:26 UTC**. На исходном сервере NOX запущен пул из трёх постоянных дочерних процессов. Полный реестр из 295 проектных пунктов передан, распределён по четырём очередям и проверен по точным SHA256. Выполнены четыре ограниченные подзадачи. Автоматическое исполнение всех исходных спецификаций ещё не подключено.

Результаты каждой подзадачи перечитаны напрямую из S03 в режиме только чтения, с проверкой точного receipt, SHA и claim. PID 3680900 последовательно выполнил проверки памяти, предпосылок обучения и очереди без перезапуска.

**Новых подтверждений полного выполнения исходных проектных пунктов: 0.** Четыре новых подзадачи имеют отдельные TaskID и флаг `original_task_accepted=false`. Регистрация 295 пунктов не равна наличию 295 исполнительных обработчиков. У 291 исходного ID нет новой исполнительной привязки; у четырёх есть только перечисленная ограниченная проверка. Это не число дефектов и не отмена прежних подтверждений.

Для дальнейшего самостоятельного выполнения реестра нужна подключённая цепочка «спецификация → конкретное действие или изменение исходников → необходимые проверки → интеграция → подтверждённый результат». В проверенном runtime нет универсального инженерного исполнителя такой цепочки. Повторные диагностические или review задания не должны засчитываться как реализация исходных требований.

## Сохранность и оптимизация

Все 1453 строки действующей очереди, существовавшие перед успешной установкой, сохранены. Добавлены ровно четыре подзадачи, итого 1457 строк. Проверенные 404 исторические claim/result записи не изменились. Для трёх прежних native review заданий отдельно подтверждено полное равенство JSON строк обеим резервным копиям до и после остановки диспетчера.

Переданы и перечитаны без изменений 230 задач, 65 идей, 60 исходных receipt records и 295 строк маршрутизации. Сохранены 11 исторических verified результатов в их исходной области: 7 source и 4 native. Остальные записи истории — 48 blocked и одна source-exact/native-HOLD; отсутствие receipt у 235 ID не трактуется как дефект.

В рабочий код внесены общий лимит три, чередование четырёх очередей, сохранение занятого слота для неопределённых claims, постоянные процессы и измеряемые статусы вместо завышенного числа исполнителей. CPU проверки используют измерение рабочей памяти и давления ресурсов; общая память модели учитывается. Подзадачи не требуют модельного вызова. Здоровье действующей модели проверяется на её фактическом порту 8098. Количественное ускорение всего проекта не измерялось.

PID и время старта действующих чата, proxy и WEB29 сохранились. Первый запуск выявил несовместимость контрольной суммы старого загрузчика и новой версии callback. Установщик восстановил прежний код и конфигурацию. Затем точная проверка источника подтвердила причину; исправлена только ожидаемая SHA callback, с сохранением самой проверки подлинности. Повторная установка прошла.

Локально пройдены 30 тестов пула/подзадач, 7 проверок установки/восстановления и 2 проверки совместимости загрузчика. Native evidence отделён от этих локальных тестов.

## Известные особенности метаданных

При первой из двух попыток чтения статуса независимый inspector получил `NO_NATIVE_STATUS`; второе чтение подтвердило все три процесса непосредственно через `/proc`. Поэтому доказательство непрерывности состоит из двух валидных снимков установщика и одного более позднего независимого снимка, а не двух валидных независимых снимков. Это согласуется с промежуточной публикацией базового статуса старым слоем, но причина этой краткой недоступности отдельно не исследована.

У завершённых подзадач сохранилась служебная note `ADMITTED_NOT_EXECUTED` от этапа приёма. Итог устанавливается по `status=done`, фазе `NATIVE_LEAF_COMPLETED_ORIGINAL_NOT_ACCEPTED` и точному S03 receipt. Очистку этой устаревшей note следует внести отдельным исправлением статуса. Она не используется как доказательство результата.
