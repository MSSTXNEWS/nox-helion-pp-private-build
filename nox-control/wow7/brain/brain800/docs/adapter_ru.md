## Внешний адаптер основной GLM

`python -m brain800.adapter_export export reviewed.jsonl dataset_new` создаёт закрытый локальный каталог. Каждая строка входа — предварительно просмотренная человеком обезличенная пара. Пример строки:

```json
{"language":"ru","approved":true,"training_opt_in":true,"training_scope":"skill","manually_deidentified":true,"personal_facts":false,"provenance":{"kind":"synthetic","id":"pause-001"},"prompt":"После перебивания как продолжить мысль, если время остановки плеера неизвестно?","chosen":"Коротко назови место, до которого мог дойти звук, и предложи уточнить точку продолжения.","rejected":"Считай, что слушатель услышал весь сформированный ответ."}
```

Для испанской пары ставится `"language":"es"`. Поля согласия — отдельные булевы значения. Положительная оценка ответа в чате сама по себе этого согласия не даёт. Для исходного обезличенного примера допускается `provenance.kind=reviewed_skill`. Исходный идентификатор — короткая непрозрачная метка. Выгрузка не читает S03, переписки, профили или ночные логи. Автоматический фильтр отсеивает распространённые контакты, идентификаторы, секреты и несколько явных фраз о человеке. Семантическое обезличивание остаётся обязанностью автора примеров. При нарушении условий весь экспорт отклоняется с номером строки, без публикации частичного набора. Для оценки навыка отложите другие синтетические задачи семейства до обучения.

Выходы:

- `sft.jsonl` — диалог `messages`, пользователь и предпочтительный ответ. `dpo.jsonl` — `prompt/chosen/rejected` с отдельными списками сообщений. Предназначены для внешнего совместимого тренера.
- `kto_train.jsonl` — две строки формата SLP для каждой пары. Положительная и отрицательная завершённые реплики имеют `label=true/false`. Файл читается существующей `SLP/train_kto_s2.py:load_rows`; в режиме `sft` её загрузчик отбирает только положительные примеры. `stats.json` и `provenance.jsonl` содержат статистику, отпечатки и происхождение.
- Существующий `SLP/train_lora_s2.sh` по умолчанию учит Qwen3-8B «спинного мозга» на S2, поддерживает KTO/SFT и не принимает DPO-файл. Ночной `SLP/sleep_cycle.py` явно отводит обучение этому компоненту. `GROW/reason/adapter.py` соединяет инструменты с ядром; `GROW/reason/router.py` выполняет выбор на CPU. Само наличие файла с именем adapter не свидетельствует о модификации весов основной GLM.

### Проверка полученного от внешнего тренера PEFT-адаптера

`python -m brain800.adapter_export validate runtime.json trained_manifest.json adapter_config.json adapter_model.safetensors`

В `runtime.json` оператор фиксирует данные из доверенной описи действительной исходной модели: `role=main_glm`, `architecture` (точный класс), `base_model` (исходный идентификатор весов), `revision` (полный SHA, 40 или 64 строчных hex-символа) и `target_modules` (точные имена участвующих линейных модулей). Имя GGUF и изменяемая метка main такой описи не заменяют. В манифесте тренера должны быть те же поля плюс `adapter_sha256` для полученного файла. Список должен соответствовать реальной архитектуре и PEFT-конфигурации; универсальный шаблон `all-linear` здесь не принимается. Файл весов должен состоять из пар матриц LoRA A/B с согласованными рангами и адресами данных в контейнере. Поддержан обычный PEFT LoRA для линейных слоёв, без DoRA, неодинаковых рангов, дополнительных сохранённых модулей и нестандартных экспертных тензоров.

Результат проверки метаданных содержит `compatible_metadata=true, loaded=false`. Доверенность исходной описи, размерности относительно **реальных** тензоров базовой модели, поддержка целевых модулей сборкой конвертера и загрузка результата целевым llama.cpp проверяются отдельно на точной модели. Если нет исходной trainable-базы, её ревизии или совместимого конвертера, модуль останавливается на подготовке данных. Он не скачивает веса, не запускает обучение и не включает адаптер на S1.

LoRA **маршрутизатора** меняет веса выбора операции. Адаптер **основной GLM** должен применяться к конкретным параметрам языковой модели и иметь совместимую базу. Срабатывание более удачного маршрута или появление нового JSONL не доказывает изменение GLM. Сравнение генерации с адаптером и без него на одном замороженном сценарии требует реально загруженного файла у обслуживающего процесса.
