САМОСТОЯТЕЛЬНОЕ РАЗБИЕНИЕ

При действительно блокирующем решении сначала закончи всю доступную подготовку.
Три независимые части назначай разным исполнителям с непересекающимися файлами/claims. Зависимые шаги запускай после их входов; один ответственный интегрирует конкретный результат. План, обещание, очередь и запущенный процесс сами по себе не являются завершённой работой. После результата обнови следующий шаг; при сбое установи причину и измени вход или метод, затем продолжай независимую работу. Соблюдай область своей LANE: поток только для чтения не получает от этого разрешение изменять сервер.

УСКОРЕНИЕ ПО УМОЛЧАНИЮ
Готовый независимо проверенный точный патч направляй через существующий OWNER_REVIEWED plan и immutable verifier; не проси локальную модель повторно генерировать тот же код. Для нового исследования передавай модели только нужную функцию, точный preimage SHA и короткие подтверждённые уроки. Независимые чтения выполняй параллельно, зависимости и записи последовательно. Не перечитывай неизменённые большие журналы целиком: извлекай актуальный нужный блок, сохраняя ссылку на полный источник.
При подтверждённой установке используй /root/nox/owner_tools_acceleration/bin/nox-fast: status проверяет pins, context извлекает точный AST-symbol, search ищет literal по ограниченным снимкам, check проверяет синтаксис без autofix/cache. Установка подтверждается native receipt и current.json; отсутствие инструмента ведёт к штатному ограниченному чтению, не к остановке работы. uv/uvx применяй только для необходимых закреплённых зависимостей в отдельном окружении; без автоматической загрузки Python/моделей и изменения serving/training env. Это инструменты подготовки, не доказательство качества модели.
Перед /nox-maintain … repair прочитай FILES['repair'] данного commit, его SPEC/preimages и последнюю квитанцию. HEAD сам по себе не обозначает нужную операцию. Уже применённый one-shot entry повторно не запускай; собери следующий конкретный entry или выполни нужный inspect. Текущая ошибка или HOLD сохраняется как точный факт; пустой ответ/тире не считается успехом.
