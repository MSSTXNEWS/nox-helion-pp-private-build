# Постоянное подключение ПК к существующему NOX

Скрипт `NOX_CONNECT_PC.ps1` предназначен для Windows 10/11 и Windows Server с компонентом OpenSSH. Он подключает ваш текущий компьютер к существующему серверу Vast **60509551**. Установка выполняется один раз в Windows PowerShell от имени администратора, под вашим обычным Windows-пользователем. После установки соединение поддерживает отдельное задание входа в систему с обычными правами пользователя.

Серверная подготовка проверена отдельно: закрытый операторский SSH-ключ остаётся на NOX. Скрипт получает только его открытый ключ, проверяет контрольную сумму и добавляет разрешение на вход для текущего Windows-пользователя. Ключ допускается только через локальный адрес ПК. Новая установка Windows SSH слушает `127.0.0.1`, обратный порт на сервере также привязан к `127.0.0.1:46051`.

## Запуск на ПК

Сохраните проверенный файл скрипта на ПК. Откройте **Windows PowerShell → Запуск от имени администратора** и перейдите в папку с файлом. Сверьте SHA-256 с контрольной суммой переданного вам выпуска:

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath .\NOX_CONNECT_PC.ps1
Unblock-File -LiteralPath .\NOX_CONNECT_PC.ps1
.\NOX_CONNECT_PC.ps1
```

Вставьте свой API-ключ Vast в локальное защищённое поле ввода. Скрипт сохраняет его в виде **DPAPI CurrentUser ciphertext**, доступного этому Windows-пользователю. Это позволяет заново получать действующий SSH-адрес существующего сервера после разрыва сети. Пароль Windows не запрашивается и не сохраняется. API-ключ не передаётся NOX и не помещается в аргументы задания или журнал.

Для другого диска и увеличенного резерва:

```powershell
.\NOX_CONNECT_PC.ps1 -DestinationRoot 'D:\NOX_HELION' -ReserveGiB 40 -ReservePercent 15
```

Папка по умолчанию — `C:\NOX_HELION`. В ней используются:

| Папка | Назначение |
|---|---|
| `BACKUPS` | Проверенные резервные копии, включая копии при недоступности или переполнении Google Drive. |
| `WARM` | Тёплые веса для последующей проверенной загрузки на NOX. |
| `ACCESS\pc-link` | Закрытая конфигурация подключения, выделенный ключ ПК, DPAPI-файл, локальные квитанции и ограниченный журнал. |

Резерв, записываемый для хранения: не менее **20 ГиБ и 10% объёма диска**, можно увеличить. Передача и проверка больших файлов выполняются отдельным `NOX_TRANSFER_PC_DRIVE.ps1` с тем же `DestinationRoot`. Само подключение не означает, что веса уже скопированы. Удаление серверного оригинала по-прежнему требует двух проверенных внешних копий, на ПК и Google Drive.

Если запуск останавливается с `HOLD_REPARSE_PATH_…`, скрипт показывает только в локальной консоли проверяемую область, номер родительского каталога и путь. Это означает обнаружение перенаправленного каталога или ссылки. Проверка остаётся включённой; существующие файлы не удаляются. При остановке **до запроса API-ключа**, если исходная папка намеренно перенаправлена, можно выбрать отдельную обычную папку:

```powershell
.\NOX_CONNECT_PC.ps1 -DestinationRoot 'C:\NOX_HELION_LINK'
```

Для последующих `Status`, `Uninstall` и передачи файлов используйте тот же `DestinationRoot`. Новая папка также проверяется до изменения файлов. Если сообщение указывает на корень диска или на конфигурацию SSH, смена папки не обходит эту проверку — сначала требуется разобраться с указанным перенаправлением.

## Проверка соединения

Проверка не требует прав администратора:

```powershell
.\NOX_CONNECT_PC.ps1 -Mode Status
```

Для другого диска используйте тот же `-DestinationRoot`. Состояние **`CONNECTED_VERIFIED`**, `Connected: True` и `Fresh: True` означает, что NOX успешно вошёл обратно на ПК по выделенному ключу с проверкой ключа SSH-сервера ПК. Статус повторно проверяется примерно раз в минуту и перестаёт считаться свежим через 150 секунд.

Соединение работает, пока пользователь вошёл в Windows, компьютер включён и не спит, а сеть доступна. После обрыва выполняются попытки с паузой 5–60 секунд. При следующем входе пользователя задание запускается автоматически. Параметры сна, Windows-пароль и общая политика выполнения PowerShell не изменяются.

После подтверждения входа скрипт записывает на NOX закрытый `pc_shell/connection.json` с режимом `0600`. В нём находятся адрес локального туннеля, пользователь ПК, открытый ключ SSH-сервера ПК, каталог хранения и идентификатор установки. Если на NOX установлен `nox_cold_drive.py`, выполняется его команда `configure-pc`, которая регистрирует SFTP-хранилище `nox_pc`. Журнал подключения содержит только время, состояние и безопасные коды ошибок; он ограничен четырьмя файлами примерно по 1 МиБ.

## Что сохраняется при установке

Существующие Windows SSH-ключи остаются в своих файлах. Для нового ключа создаётся отдельный файл, а блок `Match User` сохраняет прежний эффективный список `AuthorizedKeysFile`. Перед перезапуском SSH проверяются синтаксис и результат применения политики для текущего пользователя. При неудачной проверке конфигурация возвращается к сохранённому состоянию. Если уже используется нестандартный сервис SSH с непонятными параметрами или конфликтующими правилами, скрипт завершится с кодом `HOLD_…`.

NOX получает SSH-доступ с правами текущей учётной записи Windows, включая оболочку и SFTP. Выделенный ключ не разрешает SSH-переадресацию портов или агента. Это авторизованное подключение к вашему ПК, а не копирование его секретов на сервер.

## Удаление подключения

В Windows PowerShell **от имени администратора**:

```powershell
.\NOX_CONNECT_PC.ps1 -Mode Uninstall
```

Удаляется только задание этого подключения, его авторизованный ключ, точный принадлежащий ему блок SSH-конфигурации и выделенный ключ доступа к Vast. Прежний режим запуска SSH восстанавливается, если конфигурация и служба по-прежнему соответствуют изменённому скриптом состоянию. Чужие ключи, резервные копии, тёплые веса и сам Windows-компонент OpenSSH сохраняются.

Если сеть недоступна, локальный вход NOX отключается, а статус показывает `UNINSTALL_REMOTE_CLEANUP_PENDING`. Локальный выделенный ключ и DPAPI-файл временно сохраняются для завершения удаления серверной регистрации. Повторите ту же команду после восстановления сети. Скрипт не завершает неизвестные процессы SSH.

## Проверки выпуска и их пределы

В репозитории выполнены проверки фиксированного серверного verifier: привязка только к loopback, применение `Match` к реальному источнику SSH, проверка ключа ПК, отсутствие регистрации после неудачного входа, атомарная запись `0600`, отказ при подмене пути и чужом идентификаторе установки. PowerShell проверен штатным синтаксическим парсером. Эти проверки не заменяют первый запуск на Windows: ACL, DPAPI, установка OpenSSH и Task Scheduler проверяются на вашем компьютере во время установки.
