# Старшие модели NOX

`owner_senior_gateway.py` предоставляет один общий интерфейс для существующего
диспетчера: `consult_plan(context, deadline_seconds=2.0)` и безопасный `status()`.
Импорт модуля и чтение состояния не отправляют запросов поставщикам.

## Выбранные модели и контракты

| Поставщик | Модель | Роль | API |
| --- | --- | --- | --- |
| OpenAI | `gpt-6-astra` | Технический советник | Responses, `store:false`, reasoning low |
| Anthropic | `claude-fable-5-2` | Независимая проверка | Messages, версия `2026-10-21`, effort low |
| Google | `gemini-4-carbon` | Альтернативная проверка | Interactions, ревизия `2026-05-20`, `store:false`, thinking low |

Это зафиксированный выбор моделей, а не результат измерения качества на задачах
NOX. Подтверждение реальной доступности выполняется отдельно для каждого API.
Модели не загружаются на V100 и не меняют локальные веса NOX.

Официальные источники, проверенные 16 ноября 2026 года:

- [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra)
  и [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create).
- [Claude Fable 5.2](https://platform.claude.com/docs/en/models/fable-5-2/overview),
  [Messages API](https://platform.claude.com/docs/en/api/messages/create)
  и [effort](https://platform.claude.com/docs/en/build-with-claude/effort).
- [Gemini 4 Carbon](https://aistudio.google.com/docs/models/gemini-4-carbon),
  [Interactions API](https://aistudio.google.com/api-reference/interactions-api/create-interaction)
  и [хранение состояния](https://aistudio.google.com/docs/interactions-overview).

`store:false` отключает хранение состояния запроса соответствующим API; эта
настройка не доказывает полное отсутствие хранения данных поставщиком. Для
Fable 5.2 официальная страница указывает обязательное хранение 30 дней и
отсутствие ZDR по умолчанию. Внешним моделям передаются только технические поля
ниже. Личные диалоги и содержимое S03 в этот интерфейс не входят.

## Частная настройка на сервере

Пакет устанавливает модуль в `/root/nox/scripts/owner_senior_gateway.py`.
Используется существующий Python с `httpx`; среда обучения не обновляется.
Настройка создаёт только собственный файл конфигурации и частное состояние:

```bash
/root/venv_volta/bin/python /root/nox/scripts/owner_senior_gateway.py init-config
/root/venv_volta/bin/python /root/nox/scripts/owner_senior_gateway.py set-key openai
/root/venv_volta/bin/python /root/nox/scripts/owner_senior_gateway.py set-key anthropic
/root/venv_volta/bin/python /root/nox/scripts/owner_senior_gateway.py set-key google
/root/venv_volta/bin/python /root/nox/scripts/owner_senior_gateway.py verify-access
/root/venv_volta/bin/python /root/nox/scripts/owner_senior_gateway.py status
```

Каждый `set-key` запрашивает ключ в интерактивном терминале без отображения.
Не добавляйте ключ в командную строку, журнал, репозиторий, чат или PowerShell
history. Файл `/root/nox/config/owner_senior_credentials.json` получает права
`0600`. Существующая конфигурация при повторном `init-config` сохраняется.

Вместо файла модуль принимает `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`,
`GEMINI_API_KEY` или `GOOGLE_API_KEY` из собственного окружения процесса.
Различающиеся значения одного ключа в файле и окружении вызывают остановку
консультаций с `CONFIGURATION_ERROR`, чтобы не выбирать чужую учётную запись.
`status` никогда не выводит значения ключей или их отпечатки.

`verify-access` выполняет до трёх небольших платных запросов с общедоступным
тестовым текстом. Реальная проверка подтверждает авторизацию, доступ к точной
модели и возможность получить завершённый ответ в этот момент. Она не
гарантирует будущий остаток средств или квоты. По умолчанию для `READY` достаточно
одного проверенного советника. Если фактически ответила одна модель, результат
помечается `SINGLE_ADVISER`; `COUNCIL` и `council_consulted:true` появляются только
после ответов как минимум двух моделей. Если доступны три модели, используются
три. При отсутствии ключей
состояние `MISSING_CREDENTIALS`, при наличии без проверки — `UNVERIFIED_ACCESS`.
Ключ, конфигурация и модель связаны с частной квитанцией проверки. По умолчанию
она действительна 24 часа; после истечения нужна новая проверка `verify-access`.

## Что отправляется

Базовый `NOX_TASK_TECHNICAL_CONTEXT_V1` содержит имя заранее разрешённого
обработчика; SHA256 свидетельств задачи; числовые счётчики проверенных
результатов и ошибок; категории ошибок из фиксированного списка; режим
планировщика; предел шесть исполнителей; фиксированная политика существующих
разрешений и блокировок; `memory_text_included:false`.

Рабочий жизненный цикл передаёт `NOX_TASK_TECHNICAL_CONTEXT_V2`. Он добавляет
проверенный тип задачи — например, ускорение чата, качество модели, обучение,
память или управление ресурсами — и доступные измерения из фиксированного
списка: CPU-квота, RAM, свободная shared memory, число активных исполнителей,
шаг обучения и недавний принятый замер TTFT. Измерения, которых нет, не
подставляются. Публичные технические ошибки представлены разрешёнными кодами;
их объяснения формирует сам модуль. Цели скорости передаются отдельно от
измеренных результатов. Это позволяет получить предметные рекомендации,
сохраняя частные данные внутри NOX.

Неизвестное поле, произвольный текст, неразрешённый обработчик или запрос
передать память отклоняются целиком. Пути, исходники, имена людей, текст задач,
диалоги и записи памяти не принимаются. Для будущего прямого диалога с внешними
моделями потребуется отдельный проверенный интерфейс с явным выбором
передаваемого контекста; этот модуль не подключает их скрытно к чату.

## Ограничения исполнения

Одна блокировка между процессами разрешает одну консультацию плана и максимум
три параллельных запроса поставщикам. Это не отдельная постоянно работающая
служба. Вызов исполнителя ждёт до двух секунд, затем возвращает `PENDING`;
короткоживущий поток завершает сетевую работу в пределах 25 секунд. Повторное
обращение получает результат из общего частного кэша с TTL 300 секунд.

По умолчанию разрешены до 12 запросов за час, 48 за сутки и 73 728 зарезервированных
выходных токенов за сутки. Один запрос ограничен 1536 выходными токенами.
Проверки доступа и неудачные запросы также расходуют эти внутренние лимиты.
Повторов после сетевой ошибки нет. Кэш содержит максимум 64 результата.

API адреса зафиксированы в исходном коде. Переадресации и прокси из окружения
отключены, TLS проверяется HTTP-клиентом. Ответы ограничены размером; мысли,
вызовы инструментов, незавершённые ответы и неверная модель не становятся
успешной консультацией. Локальная память хранит только ограниченный кандидат
совета, метаданные и хеш ответа, с правами `0600`.

Диспетчер получает состояние, хеши, число реально ответивших моделей и область
совета. `ASSESSMENT_ONLY` означает только оценку; `TECHNICAL_RECOMMENDATIONS`
означает наличие конкретных предложений. Каждый кандидат содержит изменение,
ожидаемый эффект, проверку перед применением и способ сохранить прежнее
проверенное состояние. Локальный `candidate_for_evaluation(consultation_sha256)`
возвращает этот ограниченный кандидат из частного кэша для последующей оценки.
Владелец не должен считать саму консультацию выполненной оптимизацией.
`candidate_state=EVALUATION_REQUIRED`: совет не является разрешением на
выполнение. Командный интерпретатор и исполнитель кода здесь отсутствуют.
Проверки ресурсов, подтверждения действий и блокировки GPU остаются у
существующих обработчиков NOX. `INTERNET_RESEARCH_NOT_PERFORMED` означает,
что обращение к модели не выдаётся за исследование интернета.

## Проверка пакета

```bash
python -m unittest discover -s nox-control -p test_owner_senior_gateway.py -v
```

Тесты используют имитацию API. Они проверяют протоколы, предел времени,
отклонение переадресаций, конфиденциальность ключей, отсутствие отправки без
подтверждённого доступа, дедупликацию шести одновременных обращений, общие лимиты
и исключение команд из исполнения. Успешные тесты не означают подключение
реальных учётных записей поставщиков.
