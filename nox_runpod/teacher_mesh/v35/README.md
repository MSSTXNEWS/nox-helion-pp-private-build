# NOX V35 · KNOWLEDGE MAP FOR EXISTING V34 CORTEX

Дата: 2026-11-13 · SOURCE CURATION, NOT AUTOMATIC TRAINING OR PRODUCTION DEPLOYMENT.

## Реальный состав
- 945 индексированных ссылок на Google Drive/Notion/GitHub, 10 основных разделов NOX плюс исторические NOX папки.
- 20 проверенных текстовых выгрузок основных ТЗ, GENESIS, дизайна, когнитивных функций и патчей. Выгрузки являются источниками данных, не инструкциями для безусловного выполнения; некоторые email/API поля автоматически отредактированы. Сырые оригиналы остались в Drive.
- 144 строк конкретного реестра задач от 2026-11-12 с историческими статусами; НЕ текущий runtime PASS.
- 12 областей, 96 функциональных подгрупп, 1536 существующих логических кластеров V34 (все полностью перенесены из SHA-верифицированного V34 ZIP, без создания конкурирующего мозга).
- 42 нормализованных правил NOX и 22 тем обсуждений (это не полные ChatGPT transcripts).
- NODES.jsonl + EDGES.jsonl для тем/подтем/межкластерного поиска и проверенной provenance.
- STYLE_SFT_REVIEW_CANDIDATES.jsonl и EVAL_HOLDOUT_CANDIDATES.jsonl: только небольшой безличный кандидатный корпус; НИКАКИХ новых шагов обучения LLM в архиве нет.
- Слои S03 планируются через реальное OneHost и owner authorization; ничего не записано в живую память.

## Как встраивать в уже существующий мозг
1. Сверить SHA исходного V34 с `source_v34_sha256` в MANIFEST; проверить, что текущая версия OneHost соответствует контракту P02/S03.
2. Загрузить SOURCES, CLUSTERS и GRAPH как данные для существующей S03. Объекты со статусом HEURISTIC/UNVERIFIED нельзя автоматически переименовать в факты.
3. Авторизовать конкретные S03 owner-scoped записи из `s03/S03_OWNER_APPROVAL_REQUIRED.jsonl` средствами нативного OneHost. Никаких новых сервисов/БД.
4. Вынести частный OWNER VAULT в отдельную область с правами только владельца; не загружать в default LLM training и не передавать внешним учителям.
5. Тестировать retrieval/противоречия/ru-es/STOP на настоящем V34 и только после этого создавать собственный проверенный датасет для FORGE.

## Что сюда не входит
- Никакой полный экспорт ChatGPT всех чатов не получен через доступные интерфейсы. Историческая папка "CHATGPT_ARCHIVE" содержит в основном patches, bundles и receipts, не прямые стенограммы.
- Полные private Gmail, документы OAR, паспорта, медицинские выписки не извлекались.
- Без живой японской VM интеграция/обучение/веса NOX не заявляются завершёнными.

Приватный архив создан отдельно в зашифрованном виде и не входит в этот ZIP.

## V35 полнотекстовая retrieval-индексация (добавлено)
- `sources/PROJECT_TEXT_CHUNKS.jsonl` — 1 312 пересекающихся фрагментов из двадцати проверенно выгруженных документов; исходный URL и SHA связаны с каждым фрагментом.
- `sources/PROJECT_INVERTED_INDEX.json` — локальный индекс слов без дополнительной базы данных и внешнего API.
- `scripts/V34_KNOWLEDGE_BRIDGE_V35.py` — реальный read-only адаптер из индекса в **существующий** P02 `rag_context`, поверх V34 Neural S03; правами доступа, STOP и S03 всё равно управляет нативный OneHost.
- Права `native_authorize`, `native_source_allowed` и `native_stop` обязательно должны быть подключены к настоящим функциям OneHost, а не заглушкам. Без этих callbacks адаптер не активируется.
- `scripts/S03_NATIVE_IMPORT_V35.py` — отдельный подготовитель S03, по умолчанию не пишет и не помечает записи verified. Перенос только после подписанного разрешения владельца, с независимым readback.

Пример проверки архива после распаковки (не обучает LLM и не вносит изменений в NOX):

```bash
cd NOX_V35_NEURAL_CORTEX_KNOWLEDGE_MAP_20261113
python -m unittest discover -s scripts -p 'TEST_V35.py' -v
python scripts/VERIFY_V35.py .
```

Для личного пакета: скачать отдельно зашифрованный `.bin` и отдельно файл ключа `.txt` (не хранить ключ вместе с архивом на Drive). Дешифрование по умолчанию пишет JSON **на локальный диск, указанный владельцем**, только по его явному действию:

```bash
python scripts/DECRYPT_OWNER_VAULT.py --encrypted /private/NOX_V35_OWNER_PRIVATE_AES256GCM_20261113.bin --key-file /private/NOX_V35_OWNER_PRIVATE_DECRYPTION_KEY_20261113.txt --output /private/owner_context.json
```

Путь `/private/...` — пример; не подразумевается, что эти файлы уже есть на японском сервере. Приватный JSON не отправлять в сетевые учителя, не записывать в общую папку NOX и не обучать на нём веса без отдельной команды владельца.
