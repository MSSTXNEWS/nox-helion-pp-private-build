# NOX V43 — native OneHost интеграция (без нового backend)

Продуктовый контракт для установленного NOX, **не подтверждение включения**:

1. OneHost авторизует пользователя, проверяет STOP, читает действующий S03, метаданные MODEL_VAULT по подписанным receipts, состояния двух V100 (VRAM/compute/temperature), RAM/swap и диск, существующие PID активного чата и FORGE.
2. При каждом обращении пользователя главная модель NOX обрабатывает ответ самостоятельно. Внешний учитель выбирается только для сложных задач, когда проверенная выгода и права использования выше порога; никакого обязательного ожидания учителя на каждый чат.
3. По `nox.resource.plan(model_id,estimated_peak_mib)` вызывается `nox/resource_brain.py:plan_load(...)`. Это чистая функция. Ни один неавторизованный текст, страница или модель не может запускать процессы.
4. Если `OWNER_NATIVE_APPROVAL_REQUIRED`, нативный OneHost проверяет подписанный owner-grant, preimage SHA, свободную VRAM **конкретной GPU**, отсутствие текущего optimizer/незавершённого checkpoint. Только после этого host-controlled loader (существующий llama.cpp router или специально установленный diffusion backend) загружает модель.
5. `nox.resource.unload` только если NOX-native process с ролью `teacher`, `in_flight==0`, не закреплён и владелец разрешил. Никакого `kill -9`, systemctl restart не из чата, никакой остановки главной модели, optimizer или S03.
6. Если модели нет на Vast и есть подтверждённый localhost PC-router, OneHost использует только **защищённый** частный канал (например Tailscale/WireGuard со scoped authentication). На момент создания V43 такого канала нет; локальный порт ПК 18780 не доступен облаку автоматически. Не пробрасывать 18780 публично без авторизации.
7. Для GPU0 сохраняется единственный inference endpoint NOX. Для GPU1 учителя и FORGE не запущены одновременно при конфликте. Изменение контекста GPU0/CPU offload допускается только по реальным latency/VRAM benchmarks и с rollback.
8. Для S03 каждый новый source manifest использует SHA-256 файлов, идентификатор Drive или HF revision, статус cold/installed/loaded и разрешение владельца. Не создавайте вторую память и не импортируйте приватные диалоги в учителей.
9. Результаты учителей проходят независимую оценку и дедупликацию; только потом FORGE может создать тренировочный корпус. Студент обновляет собственные веса; создаются checkpoints с optimizer and weights SHA, оценка до/после и rollback. Z-Image/Wan — отдельные инструменты генерации, не текстовые учителя с прямым merge весов.
10. Контур `NOX V41` выводит 3 кольца Знания/Навыки/Веса + Общий прогресс только по реальным signed receipts. `NO_DATA` != 0% и != успешное обучение.

## Нулевая новая загрузка на Vast

Последний аудит (~16GB свободно) ниже 20GB disk reserve для checkpoints. Нельзя выполнить model download на Vast до read-only инвентаризации и проверенного offsite restore. CUDA 12.x / FP16 на Tesla V100 SM70; драйвер NVIDIA устанавливается на хосте провайдера и не обновляется inside container.

## Что нужно для физической приёмки

- Из установленного NOX получить версионную схему настоящего `run_admin`/OneHost, не придумывать HTTP route по тексту ответа.
- Тестировать 2х GPU и реальные PID, модель NOX/базовый tokenizer SHA и S03.
- Модель PC Vault скачана, SHA совпадает, процесс на ПК действительно слушает loopback и доступен через разрешённый private link.
- Сценарий `request → NOX plan → load worker → native receipt → inference → unload LRU` протестирован и не увеличивает p95 TTFT чата сверх согласованного допуска.
- Один checkpoint S03+train не потерян; обучение не перезапускалось без действительного backup receipt.
