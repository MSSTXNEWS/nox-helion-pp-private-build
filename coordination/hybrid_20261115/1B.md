## Доказанный source-дефект и проверяемая граница

В [оригинальном `worm_supervisor.py`](../../nox_runpod/teacher_mesh/v47/control/worm_supervisor.py) `audit_native_queue()` увеличивает `native_job_ids_verified`, когда отдельный `task_status` имеет синтаксически допустимый `job_id`, `native_verified=True` и `receipt_sha256` правильной формы. Внутри самой функции **нет** независимого `queue_readback(job_id)` и `s03_registration_lookup(event)` для каждого такого ID. Глобальное `s03_native_verified=True` не является отдельной оригинальной S03-квитанцией по task/job/owner/event. Следовательно, этот source-счётчик **нельзя** трактовать как 60 реально зарегистрированных и сохранённых native заданий. Это именно недостаток силы доказательства, а НЕ подтверждение, что действующий сервер выдал ложные IDs.

Соседний [`dispatcher.enqueue_approved()`](../../nox_runpod/teacher_mesh/v47/control/dispatcher.py) уже проверяет `queue_readback`, `native_task_status` и независимый `s03_registration_lookup` после каждого нового enqueue. [`native_registration_recovery.py`](../../nox_runpod/teacher_mesh/v47/control/native_registration_recovery.py) защищает orphan recovery. Не менять/не дублировать эти механизмы, не создавать второй scheduler.

**Узкий интеграционный патч для single-writer владельца original V175:** разделить `status_job_ids_seen` (source-/status-only) и `owner_queue_s03_verified_job_ids` (только действительный owner-scoped подписанный native readback). Для второго требуется один доверенный OneHost-сеанс: точный instance 60509551, source matrix SHA, уникальный native job_id, соответствующий task_id, current owner scope, `queue_readback`, original S03 event digest и `s03_registration_lookup=PRESENT` с идентичным SHA; отдельный owner native proof/receipt. Никакой входящий JSON с `native_verified: true` не может сам себя подписать. Не меняй исторический счётчик без тестов совместимости старого UI. Для RUNNING heartbeat старше допустимого окна → HOLD, не kill/restart. При STOP latch только наблюдать; любые retry/enqueue требуют отдельного fencing/lease/backup, а не этого read-only аудита.
