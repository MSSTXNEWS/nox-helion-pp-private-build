## Implemented — independently owned source files only

[1D_eval.py](1D_eval.py) is a Python standard-library-only offline **source-evidence consistency gate**. It NEVER executes models, arbitrary generated code, GPUs, server commands or S03 writes. It rejects:
- train/holdout prompt SHA fingerprint overlap, duplicated IDs/prompts, absent RU/ES/critical categories, missing SHA reviewer evidence, malformed or missing numeric telemetry, unmatched prompt/dataset/tokenizer/hardware/engine and missing owner-defined thresholds;
- RU/ES relevance and accuracy, code sandbox_pass (with network-disabled isolated executor receipt), memory owner ACL/S03 retrieval/S03 retention (with S03 receipt SHA), identity origin/limitations, emotion appropriate/non-manipulative, and historical forgetting retention;
- per-case regressions, quality pass-rate loss, p95 TTFT increase, median decode tokens/s reduction, peak VRAM bytes over budget, and measured maximum aligned absolute logit delta beyond the owner-approved policy.
- It records source_consistency PASS or FAIL from supplied evidence but ALWAYS records native_verified=false, live_promoted=false, rollback_tested=false. An offline parser cannot verify receipt signatures or prove that a grader was genuinely independent.

Run from repository root:

    python3 coordination/hybrid_20261115/1D_eval.py --selftest
    python3 coordination/hybrid_20261115/1D_eval.py --reference /private/evidence/base_adapter_holdout.json --candidate /private/evidence/merged_fp16_holdout.json --train-manifest /private/evidence/train_hashes.json --policy /private/evidence/approved_thresholds.json --out /private/results/1d_adapter_vs_merged.json

Inputs are JSON objects with run and nonempty cases arrays. Run must identify variant, base_sha256, tokenizer_sha256, generation_sha256, dataset_sha256, hardware_id, engine_build and evidence_origin=native_measurement. Each case needs case_id, split=holdout, locale, category, prompt_sha256, answer_sha256, evaluation_sha256, reviewer_receipt, category-specific boolean checks, ttft_ms, decode_tps and peak_vram_bytes. Candidate cases also need measured max_logit_abs_delta. Code cases need sandbox.network_disabled=true and sandbox.run_id; memory cases need s03_receipt_sha256. Separate train manifest has prompt_sha256 array. Policy MUST supply owner-accepted max_quality_drop_pp, max_ttft_p95_increase_pct, min_tps_ratio, max_vram_bytes, max_logit_abs_delta: no guessed defaults.

Procedure: seal the holdout independently from the training set and record fingerprints only (no private raw S03, prompts, answers or secrets). Compare active base+LoRA against safely merged FP16 with identical tokenizer, generation configuration and hardware. Repeat merged FP16 against each supported GGUF quantization/Q8/Q6/Q5 candidate, then separately measure KV-cache quantization. If serving engine differs, first establish separate engine-specific FP16 baseline; do not falsely credit weight quantization. No raw generated code is executed except in a separately authorized no-network sandbox; this evaluator reads signed receipts and verifies shape only.
