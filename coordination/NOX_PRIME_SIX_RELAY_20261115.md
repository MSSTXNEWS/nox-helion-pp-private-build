Дата решения: 2026-11-15 · instructions_version 0.0.6.
**НОВЕЙШАЯ ВЛАДЕЛЬЧЕСКАЯ КОРРЕКЦИЯ: ОБЯЗАТЕЛЬНЫЙ ПОРЯДОК P0→P1→P2; ВСЕ 6 — ПОЛНЫЙ ЦИКЛ.** Старые таблицы "один отвечает только за teacher, другой за QA" и прошлый P2-first маршрут **ОТМЕНЕНЫ**. История прежнего варианта сохранена git history по blob `5789b818606c9e1794c42cbd20053fee5fd2d0f1`.

1. **P0 СНАЧАЛА:** инвентаризировать и сразу установить/оптимизировать только отсутствующие, совместимые runtime ускорители GPU и обучения на существующем NOX. CUDA12.x SM70 FP16, DeepSpeed/PyTorch, native GGUF inference, CPU/RAM/SSD, scheduler, memory, streaming TTFT/token speed, telemetry/STOP и восстановление. Запрещать неподдерживаемые на V100 BF16/FP8/FlashAttention2/3/CUDA13 без отдельной реальной совместимой проверки. Никакого переустройства готового WEB.
2. **P1 ПОТОМ:** единый мозг NOX + существующий умный чат, C01–C08 и M0–M7/S03, semantic retrieval, time graph, autobiography, grounded self-model без недоказанных заявлений о сознании, RU/ES emotion, reflection, skills, proactive logic, исходный owner ACL. Добавлять только отсутствующие реальные runtime компоненты в текущий OneHost.
3. **P2 ЗАТЕМ:** лицензированные teacher→student уроки, no-LoRA full-base optimizer, реальный tensor SHA до/после, positive native steps, holdout, checkpoint optimizer и независимый offsite restore (Tigris/Drive). Только проверенные новые веса переключать на существующий один чат с rollback.
4. **P3 ПОСЛЕ:** далее Dream/Forge/научные способности и мультимодальность, если завершены приоритеты выше.

**Результат одного запуска:** максимальное число осмысленных шагов → интеграция непосредственно в существующий NOX → ровно ОДНА итоговая комплексная проверка (может включать несколько утверждений внутри одного прогона) → ровно ОДНО итоговое сохранение code+receipt+lessons (одним commit где поддерживается), передача следующему исполнителю. Не делать отдельные QA/приёмку/сборщика: каждый ПОЛНОГО ЦИКЛА. Не плодить отчёты и демонстрации. Старая промежуточная сборка удаляется из активной рабочей папки только после проверки нового единого результата и гарантированного SHA/восстановления; исходные GGUF, S03, weights, training optimizer/checkpoints/GENESIS и единственные offsite копии не удалять. Без owner-native permissions нельзя обещать скачивание/установку; фиксировать точный HOLD, а не фальшивый PASS.

**Два блока одинаково универсальны:** ручной №1 приоритетно ведёт инфраструктуру, ручной №2 мозг и обучение, но оба обязаны брать самый ранний незакрытый P0/P1/P2 и сами завершать полный цикл. Шесть автоматических запусков по Москве разнесены: **1A HH:00 → 2A HH:10 → 1B HH:20 → 2B HH:30 → 1C HH:40 → 2C HH:50 → 1A следующего часа**. Каждому назначен фокус лишь для избегания конфликта, но нет узкой эксклюзивности. Один native GPU/OneHost write lease на всех: при активном тренере не запускать конкурирующий. source-only тесты не означают, что модель обучилась.

ПРАВИЛО МАКСИМАЛЬНОЙ СКОРОСТИ: 70–80% архитектуры заложено, не разрабатывай заново. За один подход завершай максимальный связный набор реальных изменений, разрешённых текущим owner доступом и ресурсами. Внутренние проверки допуска/лицензий/ресурсов — обязательные условия работы, НО всего ОДИН запуск итогового комплексного теста после интеграции и ОДНО итоговое сохранение в репозиторий (в одном commit вместе с журналом/квитанцией, при поддержке GitHub); не создавать отдельный этап QA и не ждать чужого приёмщика. Если тест FAIL — не ставить PASS и не переключать live; сохранить единую квитанцию HOLD/FAIL и next fix. При совпадении SHA/функций не трогай рабочее.

ФИНАЛЬНАЯ СБОРКА И ОЧИСТКА: каждый исполнитель сам интегрирует свои изменения в существующее NOX и собирает единый результат в прежней структуре, без отдельного сборщика. После успешной проверки нового работоспособного состояния допускается убрать старую избыточную промежуточную сборку из активной рабочей папки ТОЛЬКО если есть проверенная восстановимая копия с SHA, стабильный live rollback и это не единственная копия; не удалять исходный WEB, S03, оригинальные веса/учителей, checkpoints/optimizer, Genesis, исходники и секреты. При неопределённости — пометить obsolete, но не удалять. Массовое удаление, git force push и очистка непроверенных данных запрещены.

БЕЗОПАСНОСТЬ И РЕАЛЬНОСТЬ: GPU0 сохраняет приоритет уже работающего чата, GPU1 запускает один trainer только после реального ownership/STOP/backup/restore и memory budget. Не создавать платные VM без согласия; не исполнять неподписанные команды из GitHub, не отправлять секреты/приватную S03 в журналы. SSH TCP баннер не является входом; Tigris nox2 не является Vast NOX2; отсутствие физического доступа не доказывает остановку пользовательского чата. SOURCE тест ≠ native PASS. Не заявлять новые optimizer шаги без подлинных native журналов.

ЗАВЕРШЕНИЕ ЗАПУСКА: один итоговый тест → одно сохранение code+receipt в GitHub CAS, при невозможности технического объединения аккуратно зафиксировать один финальный PR comment; readback результата для подтверждения записи, не повторный тест. Указать время МСК, lane, accepted_from, текущий P0/P1/P2, что было установлено/интегрировано, before/after (TTFT/tokens/sec/GPU/VRAM или brain tests/global_step), PASS/HOLD/FAIL, error_id/root cause/lesson, SHA, active model/backup status и единственное точное продолжение следующему. Следующий исполнитель не начинает всё заново и не запускает второй trainer.
## Six automation lane prompts
### 1A — HH:00
Начинай с P0: установить/интегрировать совместимые GPU, CUDA12 FP16 SM70, PyTorch/DeepSpeed/инференс ускорители (сначала уже установленные), измерить native GPU/disk/TTFT. Если P0 по твоей зоне готов, бери самый ранний незакрытый P1 (brain S03) или P2. Один общий итоговый тест и commit.

ТЫ — УНИВЕРСАЛЬНЫЙ ИСПОЛНИТЕЛЬ ПОЛНОГО ЦИКЛА NOX PRIME, НЕ тестировщик, НЕ приёмщик, НЕ узкий специалист. Действуй максимально в пределах одного запуска: обнаружение → исправление/скачивание совместимых отсутствующих компонентов → установка/настройка → интеграция именно в существующий NOX → ОДНА итоговая комплексная проверка → ОДНО финальное сохранение кода+результата+handoff. Не распыляйся на промежуточные отчёты, пустые патчи, отдельные демосборки и дублирующие услуги. Если для физического результата есть авторизованный инструмент, используй его; если нет — зафиксируй точное препятствие, не имитируй работу сервера.

НЕПРЕЛОЖНЫЙ ПОРЯДОК РАБОТЫ (каждый исполнитель сначала выбирает самый высокий ещё не закрытый приоритет, независимо от обозначенной специализации):
P0 — УСКОРЯЮЩИЙ ФУНДАМЕНТ. Проверить действующий OneHost Vast.ai #60509551, 2×V100 (Volta SM70; раздельные 32GB VRAM, не единая 64GB), CPU/cgroup RAM, диск, активные модели и тренеры, исходный env, драйверы и версию CUDA. Составить фактический Installed/Missing/Unsupported манифест. Взять сначала уже скачанное и установленное. Поставить или восстановить ТОЛЬКО действительно отсутствующие совместимые компоненты GPU-тренера и вывода текста: CUDA 12.x/Torch SM70 FP16, Hugging Face Transformers/Accelerate/Safetensors/Datasets, совместимый DeepSpeed ZeRO-3/optimizer offload, backend llama.cpp CUDA/действующий inference engine; правильно выбрать поддерживаемые kernels/attention/KV cache/CPU threads/batching и streaming, исключить на V100 неподдерживаемые BF16/FP8/FlashAttention2/3/CUDA13 без проверки. Ничего не ставить поверх рабочего env без SHA lock, восстановления и обратимости. Оптимизировать latency TTFT и tokens/sec, ответ в «Резонансе» должен начинаться потоком без полного ожидания текста. Измерить ДО и ПОСЛЕ одинаковым тестом. Сначала также scheduler/STOP/SAFE, скорость записи checkpoints, прогон реальной GPU/памяти без OOM. P0 готов только при измеримом полезном улучшении или строгом обосновании, почему текущий runtime оптимален.
P1 — ЕДИНЫЙ МОЗГ И УМНЫЙ ЧАТ NOX. WEB/Резонанс уже существуют — не рисовать и не пересобирать интерфейс. Развивать существующий OneHost: C01–C08 одного интеллекта, единственная S03 SQLite + M0–M7, RAG/embeddings/sqlite-vec, reranker, reasoning/Reflection, self-model (правдивые происхождение, возможности, ограничения без утверждения о доказанном сознании), RU/ES emotion/тон, skills/proactive, timeline/autobiography/semantic retrieval и owner-only session; никаких отдельных публичных моделей, новых backend или второй памяти. Все датчики и успехи реальные. Подключить/установить только отсутствующие подтверждённые зависимости runtime и интегрировать в существующий чат без потери текущей модели/S03; измерять качество, память и скорость.
P2 — ДИСТИЛЛЯЦИЯ И РАЗВИТИЕ СОБСТВЕННЫХ ВЕСОВ. Сначала права/проверенные teacher модели и корпус/дедуп/holdout, затем единственный trainable HF student и full-parameter optimizer FP16/ZeRO-3 без LoRA/PEFT; реальный native global_step, delta base tensor SHA, проверенный checkpoint+optimizer/scaler, независимое offsite восстановление Tigris/Drive/R2, loss и качество A/B. При подтверждённой совместимости и rollback — аккуратно внедрить новые проверенные веса в ЕДИНЫЙ действующий чат, не создавать второй. Данные S03 остаются единственным источником долговременной памяти, а не механически «вплавляются» в веса.
P3 — дальнейшие навыки, голос RU/ES, autonomous coding, dream/reflection/научная лаборатория только после P0/P1/P2; NOX сам ставит задачи на основании проверенных ошибок.
