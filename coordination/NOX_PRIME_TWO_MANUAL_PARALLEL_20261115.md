# NOX PRIME — 2 ручных блока, ONEHOST и RAM-FIRST

**Дата:** 2026-11-15 · **instructions_version 0.0.6**. Это рабочий контракт в существующем NOX, не проект нового продукта. Актуальные источники: PR #256, \`coordination/NOX_PRIME_SIX_RELAY_20261115.md\`, \`coordination/NOX_PRIME_6_RELAY_RECEIPTS.jsonl\`, \`coordination/NOX_AUTOCYCLE_ERRORS.jsonl\`, Notion Agent Operating Guide и общий журнал. Предыдущие значения не выдаются за свежий runtime.

**Обязательная рамка:** 1×NOX / 1×«Резонанс» / 1×каноническая S03 / 1×native OneHost / GPU0 чат, GPU1 максимум один авторизованный trainer; исходные модели и контрольные точки не удалять без внешнего восстанавливаемого дубликата. Не создавать сервер, модельный «зоопарк» в интерфейсе, новый scheduler, Windows EXE, ботов или бизнес-демо. Шесть AUTO работают с теми же очередью и handoff; два MANUAL исполняют свои независимые блоки.

## Блок №1 — физика, RAM, Forge, SSD, аварийный STOP

**Владелец:** ручной Исполнитель №1. Эксклюзивные области: \`v43/nox/resource_brain.py\`, \`v71/ram_policy.py\`, \`v71/one_prime.py\` (только RAM/admission с синхронизацией №2), \`v95/ram_weight_prepare_once.py\`, \`v99/ram_first_weight_policy.py\`, \`v135/train_full_base_zero3.py\`, \`v66/v69/v70\`, V51 owner-native доступ; их тесты. №2 в эти файлы не пишет.

1. **P0 STOP сейчас:** идентифицировать GPU1 процессы по GPU UUID + pid-namespace, supervisor/OneHost lease, checkpoint и действующий чат. Только owned trainer → штатный STOP → native readback. Если PID/lease не доказан, \`HOLD_UNOWNED_GPU1\`, не \`kill -9\` широким шаблоном. Изменение GPU1 не должно остановить GPU0.
2. **P0 V100:** CUDA12/SM70 PyTorch, cuDNN/NCCL/DeepSpeed/FP16, GPU-only совместимость, RAM/cgroup/SSD, onehost GPU Resource Brain, STOP/OOM и защита main. Пакеты ставить только если native missing и есть rollback. Проверить TTFT/p50-p95/token/sec до/после и здоровье модели.
3. **P0 COLD → WARM → HOT:** COLD — шифрованные offsite веса с SHA/лицензией/restore. WARM — только проверенные локальные HF/GGUF в **вытесняемый OS page cache** V95/V99, не pinned \`/dev/shm\` и не дополнительная копия на SSD. Для удалённого источника — требовать отдельный owner-bound streaming remote→RAM(tmpfs/memfd) loader с SHA/format readback; до него \`HOLD_RAM_ONLY_REMOTE_LOADER_NOT_NATIVE_BOUND\`, никогда не объявлять загрузку выполненной. HOT — одна активная пользовательская модель GPU0, GPU1 только по verified lease. LRU/priority/idle timeout и preemption; все модели сразу в RAM физически не вмещаются. RAM данные пропадают при перезапуске: S03/checkpoints остаются долговечно offsite/SSD.
4. **P0 диск:** сначала SHA manifest/inode+path+bytes+open-fds/lease, verified remote copy и **restore**, рабочая replacement версия, только потом обязательно удалить все объекты \`SUPERSEDED_VERIFIED\` из активной рабочей области по конкретному allowlist. readback \`exists=false\`, \`df\` before/after, \`freed_bytes_actual\`. Без verified restore — HOLD; ни исходные единственные веса, ни S03/WAL, оригинальный WEB, checkpoints+optimizer, единственный offsite backup не трогать. Никаких \`rm -rf /root/nox\`/массовых glob/force push. Для regenerable pip cache использовать существующий V66.
5. **P2 собственные веса:** единственный обучаемый HF student, teacher licences, приватный train/holdout S03-free corpus, full-base FP16 ZeRO-3 без LoRA, optimizer steps + SHA tensors до/после, holdout/regression, checkpoint+optimizer/scaler и независимый offsite restore, лишь затем promotion с rollback. Обучение в scheduler допускается только при chat idle, STOP off, GPU1 lease, SSD reserve и backup readback. Не обещать непрерывную нагрузку 100% при риске OOM.

**Приёмка №1:** GPU1 ownership и STOP receipt, 2 V100 telemetry/lease, installed-vs-missing, RAM warm native bytes+page-cache+cgroup before/after, SSD actual freed bytes, true optimizer global_step + checkpoint restored and new SHA, chat 8081 healthy and before/after TTFT. Если нет хотя бы одного — честный HOLD и один следующий шаг, а не общий PASS.

## Блок №2 — один развитый ум, постоянное обучение знаний, эмоции, WEB

**Владелец:** ручной Исполнитель №2. Эксклюзивные файлы: \`v38/synaptic_brain.py\`, \`v39/learning_cycle.py\`, \`cognitive_overlay.py\`, \`cognitive_emotion_local.py\`, \`nox_emotional_resonance_v28.py\`, \`v71/one_prime.py\` (только cognitive/Resonance по согласованному API), original owner S03/RAG и WEB «Резонанс» + их тесты. №1 в эти файлы не пишет, за исключением согласованного RAM-method патча с точным SHA.

1. **P1 C01–C08 / M0–M7:** одна достоверная S03 + temporal graph, significance, persona/ACL isolation, source citations, owner-approved RAG/embeddings/reranker, bounded reflection, skills and truthful self-model/biography. Проверить сохранение→перезапуск→восстановление, отсутствие утечки PersonaID и незаявленной памяти.
2. **Постоянное обучение ЗНАНИЙ**, не путать с весами: existing OneHost periodic cycle (не второй daemon). Source/license/privacy → dedup → quality/contradiction evaluation → owner-scoped durable S03 index → retrieval → independent holdout → feedback/reflection → lessons/skill memory; checkpoint курсора и ошибок, pause на STOP/смене owner session/проблемах с RAM и DB. 24/7 означает автоматическое продолжение по безопасным окнам, не безграничную загрузку CPU/GPU.
3. **Эмоции RU/ES:** безопасная реакция на тон текста, подтверждённые S03 предпочтения, эмоции как функциональная модель поведения, а не диагноз пользователя/доказанное сознание. Один пользовательский NOX, без отдельной CPU-персоны, чувствительных записей и автоматической загрузки сторонней модели без лицензии.
4. **Множество функций, одна модель:** registered tools/teachers (voice RU/ES, vision, science, code, automation, movies/creative), router выбирает по задаче и реальному наличию RAM/VRAM; внешние модели не становятся самостоятельным публичным чатом. При отсутствии ресурса честный fallback, без задержки первого токена от обязательного ожидания учителя.
5. **Резонанс WEB:** реальный first token/final/STOP SSE, S03 owner-auth write/readback, C01–C08 effect on response, confidence, latency and quality measured on same 10-20 RU/ES questions, no false \`saved=true\`, no placeholders. Не рисовать новую WEB.

**Приёмка №2:** S03 2× durable source-linked tests, C01–C08 present in real turn receipts, retrieval/contradiction evidence, emotional-style test RU/ES, one tested automatic learning cycle with persisted resume/STOP, zero inter-persona leakage, real stream with TTFT/full and no broken chat.

## Параллельность и один мастер

- **Параллельны** source development, unit tests, read-only monitoring, knowledge corpus validation and CPU tasks. **Не параллельны** GPU1 native trainer, DB writer/backup/restore, promotion, file deletion, or merge into shared feature HEAD.
- На сервере OneHost lease: \`gpu1_writer=manual1_or_auto_one\`, \`s03_writer=manual2_or_onehost\`, \`artifact_delete=manual1\`. Всегда owner-auth native fresh STOP/lease state; никакого враждебного kill чужих процессов.
- №2 отдаёт №1 **только** SHA-pinned, licensed, de-identified/approved training manifests с disjoint holdout/learning objectives; №1 возвращает verified optimizer/checkpoint/capability receipts. Это коммуникация, не копирование приватной S03.
- Общие файлы \`coordination/*jsonl\` и source branch — **ОДИН CAS writer за раз**, два MANUAL могут писать независимые ветки/свои paths, потом последовательные merges; AUTO обязан уважать leases и читать последнюю квитанцию. Нет блокирующей ручной QA роли: каждый сам тестирует, один итоговый результат и один код+receipt commit.
- Перед merged release проверить NO-LOSS, original model/S03 WEB readback, checkpoint and remote restore. Обязательная физическая очистка всех \`SUPERSEDED_VERIFIED\` объектов — отдельный post-replacement этап *внутри того же принятого релиза*, но никогда до independent restore.

## Дополнительные забытые зависимости

Модельный manifest должен содержать SHA, provenance, licensing, quantization/HF trainability, active process/fd leases, on-disk/cold location и recent uses. Качество держать на holdout и regression, раздельные RU/ES, безопасность промптов/инструментов, Privacy/Persona. Переиспользовать единые готовые модули V38/V39/V43/V66/V71/V95/V99/V135, не переписывать. Регулярно наблюдать RAM pressure/PSI, disk fsync throughput, GPU temperature, actual utilization, restart recovery, optimizer checkpoint corruption и деградацию TTFT при background tasks. Версия релиза определяется реальным code SHA + model SHA + S03 backup revision, а не числом workflow или процентами задач.
