# NOX HELION · GENESIS CORE STAGE 0 · owner priority 2026-11-06

instructions_version: 0.0.6
Status: ARCHITECTURAL DIRECTION; not a released or tested self-programming system.

## Immediate goal
Build the smallest **real** NOX core that can read its own existing project, understand its approved specification, plan, write candidate code patches, test them in isolation, and gradually improve its own Windows NOX HELION application. Do not build full personalities, fantasy worlds, emotional life simulations or train massive independent models before this core can actually perform useful owner-approved tasks.

## Preserve future architecture without premature implementation
Canonical design has ONE NOX identity, eight functional CoreID (CONSCIOUSNESS/PERSONA/ATLAS/VOICE/REFLECTION/CORE/NEXUS/FORGE), five PersonaID (KV/AM/LA/EV/KW), each with distinct memories, trait sets, emotion/behavior algorithms and development histories. Do not collapse PersonaID into CoreID, or present underlying LLM weights as standalone personalities. At this stage they are future-compatible interfaces/schema only, not evidence of implemented full behavior.

## Genesis milestones
G0: Start existing NOX.HELION.exe, recognize operator identity via existing native auth, identify installed model runtime and actual machine hardware.
G1: One NOX answer through current native chat, with honest, durable self-model, scope-limited memory, native STOP and provenance.
G2: Read-only indexed project source through existing repository/Drive integrations; build source tree map and identify relevant files.
G3: Generate an isolated, verifiable candidate patch and list affected files; no automatic application to stable release.
G4: Execute real project tests in an isolated working tree, inspect failures, revise patches within bounded iterations.
G5: Commit only with required project approvals and native release gates; backup and rollback available.
G6: Record evidence and verified lessons to existing S03, show authentic progress through the existing FORGE dashboard; evaluate benchmark against baseline before any new weight adapter is promoted.
G7: Enable bounded, resumable loops only after functioning G0–G6; obey thermal safety 65C -> >=180s cool and resume <65C, disk 70/70/70 GB with 60GB free reserve, no Downloads, no redundant model pulls, battery-aware throttling/shutdown checkpoints.

## Non-negotiable
- Single existing Windows app; no second competing UI/backend. Use PR #162 and present original native owner contracts.
- Avoid fake PASS, fake intelligence scores, fake consciousness or fabricated trained weights.
- Owner can permit human-like emotional expression and scenario behavior; such expressions are not evidence of subjective experiences.
- Current code/source staging is not physical integration until Windows execution/independent acceptance.
- No background autonomous changes to source, installed EXE, data permissions or user files without verified authorization.
- Do not delete original learned weights or existing S03 memory.
