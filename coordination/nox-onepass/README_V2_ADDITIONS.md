# NOX ONEPASS V2 — инженерная приёмка без ложного PASS

Дата: 2026-11-12. Основа: проверенная 10-страничная WEB V25.1, source SHA `b55e9979765ea35449a99f7dc54917cfedcd65bb`.

## Изменения исполнения

- Физическая проверка Windows/Edge не считается действующей только потому, что когда-то в state.json стоял PASS: необходимо повторное чтение `qa-report.json`, аппаратный renderer, все условия и SHA-256 семи настоящих PNG. Доказательство старше 24 часов не проходит повторную приёмку.
- Chromium PASS повторно сверяется с реальным source SHA, всеми 7 размерами экрана, 10 страницами, пятью функциональными сценариями, оригинальным аудитом V7 и хэшами семи скриншотов. Утраченный отчёт или подменённая картинка сбрасывают статус.
- Для FULL_ACCEPTED дополнительно необходимы реальные подтверждения голоса RU/ES и координатора обучения, собственных весов, отдельной приёмки STOP/S03 с SHA транскрипта и согласованный владельцем визуал именно этого source/manifest.
- При появлении `NOX_STOP` отменяется **только дочерний процесс тестирования**. GPU-тренер/RunPod/Windows не перезагружаются.
- Проверка локального OneHost по умолчанию read-only. Никаких тестовых сообщений без явного `NOX_ALLOW_TEST_CHAT=1`, повтор после неопределённого POST запрещён.

## Проверка

На Node.js 22+ из корня пакета:

```powershell
node --test .\test-onepass.mjs
$env:NOX_PREFLIGHT_ONLY='1'; node .\NOX_ONEPASS.mjs
```

Для полноценной проверки на физической Windows машине с GPU и действующим NOX: `& .\START_NOX_ONEPASS.cmd`. Она не делает кодовые изменения автоматически и не создаёт фальшивый backend. Если устройство или endpoint недоступны, сохраним `HOLD`, а не 100%.

Код исполнителя и описание — в отдельной GitHub ветке NOX без изменения production. Для продолжения работ над настоящим OneHost/Windows нужен подтверждённый доступ к устройству в соответствующей сессии. Воспроизводимые ошибки исправлять в исходниках, затем повторять все гейты на одном SHA; никаких бессрочных циклов без верифицированного результата.
