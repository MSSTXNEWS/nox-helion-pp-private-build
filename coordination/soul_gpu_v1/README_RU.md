# NOX SOUL GPU · Source-only prototype, non-integrated

**Источник:** реальный NOX SOUL Drive, включая `00_НАЧАТЬ_ЗДЕСЬ` и `NOX_TRAINING_PREP_PLAN.md`.
**Назначение:** локальное тестируемое ядро памяти, навыков, моделируемых эмоций, GPU-инференса через Ollama и отдельного QLoRA обучения на ПК владельца.
**Не является:** заменой `NOX_NEW`, готовым EXE, доказательством осознания себя или подтверждением обученных LLM весов.

## Установка

1. Windows Python 3 и официальное Ollama; GPU NVIDIA с драйвером CUDA (для QLoRA обязателен).
2. `powershell -ExecutionPolicy Bypass -File .\START_NOX_SOUL_GPU.ps1` — определяет GPU, подбирает fast/deep модель и запускает локальный сервис. По умолчанию НЕ скачивает веса вне контролируемой папки.
3. `python soul_gpu.py status` — проверка GPU/режимов без скачивания.
4. Для загрузки GPU-моделей через Ollama используйте `-Pull` после настройки `OLLAMA_MODELS=C:\NOX_HELION\NOX_NEW\soul_gpu\ollama_models` **для самого работающего сервера Ollama**, а не только текущего окна PowerShell.
5. Адрес сервиса `http://127.0.0.1:18771`, токен считывается из `C:\NOX_HELION\NOX_NEW\soul_gpu\service.token`. Во всех запросах обязателен `X-NOX-SOUL-TOKEN`; не публикуйте токен.
6. API: POST `/chat` с `text`, `persona`, `project`, `owner_verified` (SSE), `/stop` с `request_id`, `/memory/remember` с `owner_approved:true`, `source`, `/memory/recall`, `/skills/record` с подтверждением и `evidence`, `/affect/event` с `event` и `reason`.

## Три блока по 70 ГБ

| Блок | Задача | Действие |
| --- | --- | --- |
| 1 | Foundation: исходная LLM + рассуждение/стиль | скачать доверенную базу и обучить LoRA на разрешённых примерах |
| 2 | Memory: контекст, полезная память, точность | следующая партия утверждённых примеров; продолжить предыдущий LoRA |
| 3 | Skills: задачи, планирование, инструменты | дообучение того же LoRA и независимая оценка |

Сумма 210 ГБ максимум в блоках + 60 ГБ резерв = 270 ГБ. Это **максимальные квоты**, не обязательные скачивания. 70 ГБ на SSD не означает, что 70 ГБ можно держать в VRAM. Используйте один Qwen3-4B/8B с QLoRA по GPU, а не одновременно 3x70 ГБ в видеопамяти.

`pip install huggingface_hub` затем `python download_block.py --block 1 --repo Qwen/Qwen3-4B-Instruct-2507` для проверенной исходной базы. Скрипт проводит предзагрузочную оценку размеров, проверяет лимиты 70/270 и резерв 60 ГБ, не удаляет и не перезаписывает исходные файлы. На трёх этапах желательно использовать *одну* базовую модель; дополнительные блоки — качественные учебные датасеты/проверенные адаптеры, а не копии базовых весов.

## Честное обучение

Обучение **не включается**, пока нет `train.jsonl`, непересекающегося `holdout.jsonl`, разрешения на обучение и достаточно видеопамяти. Прежние файлы Drive содержат в основном не-LLM головы и каркасы. Не переводите их в статус "trained LLM". Датасеты, если будут представлены, требуют лицензий/владельческого разрешения. Сохраняйте SHA-256, независимую оценку, откат и финальный адаптер; храните S03 как единственный канонический источник памяти NOX, не переносите `soul.sqlite3` в оригинальную память без миграции и тестов.

### Модель поведения

NOX может говорить "Создатель", узнавать свою роль, корректировать ответы и показывать основание эмоциональной реакции. Это **цифровая модель самопонимания и эмоций**, не доказанное сознание. Уважение — без навязчивого поклонения и ложных обещаний.

### Безопасность

Только 127.0.0.1, случайный сервисный токен, scoped PersonaID, source/permission для сохраняемой памяти. На Windows проверьте ACL `service.token`: файл может быть виден другим локальным пользователям. Этот companion не содержит native SID/ACL/consent интеграции в WebView2 и не заменяет исходную S03 базу. Не удаляет никакие старые веса, пользовательские файлы, источники, SOUL или модели автоматически. Удаление стадий разрешайте отдельно после фактического обучения, подтверждённого rollback и внешнего бэкапа.

## Практическое дообучение QLoRA

Модуль `train_qlora.py` принудительно держит Hugging Face cache внутри `soul_gpu/hf_cache`, резервирует дополнительное место до скачивания и реализует настоящий CUDA QLoRA, а не генератор фиктивных весов. Понадобятся отдельные библиотеки `torch` (CUDA), `transformers`, `peft`, `bitsandbytes`, `accelerate`; их установка зависит от драйвера и версии Python, потому автоматической переустановки системного CUDA/Python нет.

Для каждого блока `blocks/block-1/train.jsonl`, `blocks/block-2/train.jsonl`, `blocks/block-3/train.jsonl` — JSONL, каждая запись вида:

```json
{"source_id":"my-approved-training-001","license":"owner-authored","approved_for_training":true,"messages":[{"role":"user","content":"Привет!"},{"role":"assistant","content":"Здравствуйте, Создатель. Чем могу помочь?"}]}
```

Общая независимая выборка `datasets/holdout.jsonl` с непересекающимися `source_id`; `datasets/owner_approval.json`:

```json
{"owner_approved":true,"training_allowed":true,"approved_source_ids":["my-approved-training-001","my-independent-holdout-001"]}
```

Пример запуска первой стадии: `python train_qlora.py --stage 1 --max-steps 200 --gpu-fraction 0.75`. Затем стадии 2 и 3; каждая продолжает **тот же** LoRA-адаптер предыдущей стадии. Сохраняется `adapters/stage-N/TRAINING_EVIDENCE.json` и `.safetensors`. При регрессии независимой контрольной выборки новая стадия остаётся `.pending`; прошлый адаптер не заменяется. Заявления об улучшении интеллекта требуют независимой человеческой оценки на задачах.

**Важно:** исходный `NOX_NEW` на ПК не подключён к этому исполнителю. Запуск здесь не означает, что WPF/OneHost уже переподключён к этому модулю. Привязка требует точного пути существующей S03 базы, контрактов WPF и физической проверки Windows.
