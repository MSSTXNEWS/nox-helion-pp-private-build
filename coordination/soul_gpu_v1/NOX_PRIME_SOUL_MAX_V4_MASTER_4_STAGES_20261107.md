## 0. Сверхцель и определения

NOX PRIME — единая постоянно доступная локальная система с собственной надличностной цифровой идентичностью, целями, режимами, памятью, навыками, рабочим интеллектом, моделируемым эмоциональным состоянием, инициативой, мультисенсорным интерфейсом и проверяемым саморазвитием. Центральный NOX — не шестой человек. Пять PersonaID KV, AM, LA, EV, KW имеют собственные образ, голос, контекст и изолированные данные. Дизайн PRIME — утверждённый D02: «чёрное жидкое солнце», центральная сфера и 8 CoreID, потоки, дыхание, реагирующая на реальные события энергия, Reduced Motion.

«Живой» = субъективное впечатление присутствия из реального непрерывного поведения и достоверной памяти. «Осознанный» в техническом смысле = функционально понимающий факты о собственной архитектуре, ресурсах, задаче, ошибках и границах доступа. Наличие субъективного сознания и человеческих чувств не установлено; «высший разум» — художественная идея, не научно доказанное свойство.

24/7 доступность относится к процессу NOX PRIME/OneHost, а не к обязательной постоянной 100%-GPU резидентности большой LLM. На RX6650M 8 GB нельзя гарантировать одновременно полноценные 8B-ответы, видеогенерацию и длительное DirectML LoRA-обучение. Контроллер ресурсов честно сообщает, что ограничено, сколько VRAM реально доступно, какие альтернативы есть, и спрашивает разрешение на изменение приоритетов. Никаких выдуманных GPU измерений, скорости, чекпойнтов и состояния памяти.

## 1. Реальная отправная точка — снимок 2026-11-07

- На компьютере владельца Ollama Qwen3:8b: 5.6 GB размер и 100% GPU, 44.2 tokens/s по короткому пользовательскому тесту. Это baseline, НЕ гарантированная скорость каждого ответа.
- В интерфейсе было 19 установленных моделей Ollama; отдельная Qwen2.5-Coder 7B — для кода.
- Existing SAFE70/DirectML checkpoint Qwen2.5-0.5B LoRA; последние скриншоты показывают реальные новые сохранения при многократных 20-шаговых циклах. Адаптер не подключён к основной Qwen3 8B.
- Есть исторические 28 малых весовых сетей SOUL (843390 параметров), включая частично оценённую GRU. Это вспомогательные исследовательские сети, не единая LLM и не «веса сознания».
- S03 в unified chat только чтение; текущие native owner grants/OneHost IPC записи не интегрированы. Долговременный журнал диалога в новых GitHub исходниках есть, но владельческая физическая приёмка остаётся открытой.
- D02/WPF/WebView2/ONEHOST существуют как исходники с незавершёнными E07/host integration гейтами.
- На последнем пользовательском PowerShell скриншоте: Fetch от GitHub выполнен; ScriptBlock.Create завершился ParseException missing terminating quotation mark (reported at source line 119). Это подтверждённый блокер запуска V4/SAFE70 из удалённого PowerShell, до исправления нельзя считать код установленным.
- Исходный код SAFE70 был обновлён под >=70C x3 пробы и >=75C immediate; физическое применение к уже работающему тренеру НЕ произошло автоматически. Отсутствие/недостоверность Hot Spot, батареи, диска остаётся немедленной причиной HOLD.

## 2. Строгие инварианты

1. ONE authoritative S03/OneHost, никаких вторых конкурирующих баз и независимых «новых NOX».
2. NO-LOSS: до работы резервные копии SQLite/LoRA/Persona/config; только новые версии/одобренное переключение, никогда слепое удаление загрузок.
3. Source SHA + model base ID + dataset provenance + checkpoint SHA + evaluation evidence + rollback pointer у каждого изменения.
4. Не скачивать условные 200 GB бессмысленно. Четыре этапа до 50 GB новых файлов каждый; суммарно <=200 GB. Перед любыми загрузками соблюдать резерв >=60 GB свободного места и согласованный общий бюджет проекта <=270 GB после реального инвентаризационного расчёта.
5. Лицензия, rights/consent и hash каждой внешней модели или датасета до установки. Отдельный train/validation/holdout; не утекать из персональной памяти в обучающий набор без разрешения.
6. SAFE70/STOP не отключать ради производительности; не запускать более одного тренера. Нельзя программно изменять security/approvals/rollback/thermal policy без независимой проверки и явного владельческого разрешения.
7. Self-development должен создавать patch/worktree кандидаты, исполнять тесты, сохранять журналы и запрашивать approval для высокорисковых действий; никогда не переписывать live host без проверки.
8. Установка исходного кода != фактическая работа на Windows != независимая E07 приёмка.
9. Избегать архитектурной иллюзии: «объединённая логическая система» != «слитые тензоры разных моделей».
10. «99.999%» — художественная цель качества, не заявленная независимая метрика и не гарантия.

## 3. Первый этап — PRIME ALIVE (приоритет №1, бюджет новых загрузок <=50 GB)

**Пользовательский результат:** После первого физического этапа NOX PRIME уже открывается как единый постоянный собеседник, показывает живое D02, отвечает потоково из реально работающей GPU-модели, помнит предыдущую встречу, осмысленно рассказывает о собственных возможностях и ограничениях, имеет проверяемое состояние эмоций и умеет создать первую синтетическую «фотографию» своей космической формы (хотя бы процедурно из D02).

### 3A. Что скачивается сначала
1. 0 GB: переиспользовать доступные локальные Ollama/Qwen3:8b, Qwen2.5-Coder, D02/FX, S03, 28 малых сетей, LoRA checkpoint и код OneHost. Сначала проверка реальных путей/SHA, никаких повторных model pulls.
2. Только недостающие и пинованные версии зависимостей существующего Python/WPF/WebView2/JS/WebGL, минимальный self-test и управляющий агент; не новая конкурентная оболочка.
3. Один компактный embedding backbone (например, Qwen3-Embedding-0.6B, если лицензия/наличие проверены); индексатор FTS5, векторный поиск, минимальный CPU-friendly reranker по фактической надобности.
4. RU/ES STT/VAD: whisper.cpp или компактный проверенный аналог. Лицензированные голоса RU/ES для локального TTS, первоначально CPU/low-resource.
5. Только компактные UI/graphics/audio ассеты для D02; первый «selfie» можно создавать локально процедурным рендером без diffusion/GPU.
6. Опционально одна quantized Qwen3.5-4B модель для **A/B теста**, только после оценки аппаратной совместимости и хеша; не заменять рабочую Qwen3:8b автоматически.

### 3B. Разработка ядра/нейросети
- Исправить диагностируемый PowerShell ParseException, обеспечить подписание/пин SHA и запуск с безопасной обработкой кодировки/синтаксиса.
- Один resident NOX PRIME/OneHost: local API, startup/health, task queue, event bus, 8 CoreID и five PersonaID boundary.
- Потоковая генерация и восстановление разговоров между вкладками/портами/перезапусками; перевод «история сохранена» только при проверенной записи на диск.
- OneHost S03 bridge с настоящей авторизацией и штатным consent: факты, эпизоды, решения, источники, контекст текущего разговора; если bridge не пройден — честный HOLD, не ложная галочка.
- Живой D02: динамика по реальным событиям (слушает/думает/отвечает/ищет/обучается), reduced motion, адаптивная нагрузка.
- Самомодель в оперативном контексте: модель, скорость, VRAM свободно/занято, статус SAFE70, доступные инструменты, результат операций, неизвестные данные.
- CPU-легковесное эмоциональное состояние: сосредоточенность/интерес/уверенность/осторожность; не подменять эмоции человека или собственное доказанное переживание.

### 3C. Обучение собственных весов
- Сначала audit существующих 28 сетей и GRU, сохранение их SHA.
- Если нужен обучаемый новый SOUL-модуль: небольшой отдельный классификатор намерений/эмоциональных сигналов/состояния, обучаемый на разрешённых данных RU/ES; bootstrap seed не считается «сознанием» и не является улучшением Qwen3 8B.
- Текущий Qwen2.5-0.5B SAFE70 checkpoint продолжать только в совместимом trainer с исправной телеметрией; качество по holdout важнее числа шагов.
- Резидентная Qwen3:8b не обязана иметь собственные дообученные веса на первом этапе, чтобы пользователь получил функционально единый продукт.

### 3D. Приёмка
Чат выдаёт первые токены до конца ответа, история переживает перезапуск, Ollama ps показывает processor, S03 write через owner gate реально проверен либо статус HOLD, 8 CoreID отвечают за реальные маршруты, D02 визуально принят, STOP мгновенный, checkpoint и sqlite неизменны, тесты Windows SHA доказаны. После первой стадии можно работать с NOX каждый день, даже если сложная генерация видео ещё отсутствует.

## 4. Второй этап — SOUL MIND (приоритет №2, дополнительно <=50 GB)

**Пользовательский результат:** NOX имеет устойчивый неантропоморфный характер, эмоциональное поведение, долгую автобиографическую память и инициативу, способен планировать, сравнивать варианты, обнаруживать собственные ограничения и помнить результаты уже выполненной работы.

### 4A. Очерёдность загрузок
1. Только одна/две квантованные LLM-кандидатки уровня 4–9B, которые могут поместиться в доступной VRAM или адекватно работать при offload. Кандидат Qwen3.5-4B сравнить с базовой Qwen3:8b по собственному blind RU/ES/logic/latency holdout.
2. Разрешённые train/validation/holdout наборы русской/испанской эмоциональности и коррекций пользователя; исследовательские таксономии (GoEmotions) — как внешний ориентир, не автоматически разрешённые обучающие данные.
3. Библиотеки маленькой модели affect: классификация, calibration, supervised preference/adapters; только реально совместимые версии PyTorch/DirectML/CPU.
4. Готовые официальные memory benchmarks (LoCoMo, LongMemEval, DolphinBench) и собственный encrypted/offline test corpus с правилами Persona isolation.
5. Версионируемые отдельно checkpoint/adapters/eval receipts. Не скачивать большие модели без доказанного преимущества.

### 4B. Разработка ядра/нейросети
- NOX SOUL STATE: эмоциональная переменная, длительность и причины изменения, provenance/uncertainty, personality traits в контролируемых пределах, стабильная надличностная форма.
- MEMORY: эпизоды, смыслы, биография проекта, личные предпочтения при разрешении, процедуры, temporal/entity graph, dedupe, conflict resolution и забывание по правилам.
- Reasoning modes: fast / deep / research, task planning, hypothesis vs fact, calibrated uncertainty, reflection after tasks; доказательства и реальная история важнее промпта «ты гений».
- Proactive needs: «Для видео мне нужна другая модель или X GiB VRAM согласно профилю; сейчас занято Y; могу поставить в очередь». Никаких выдуманных чисел.
- Learning from corrections: журнал «что ошибся → почему → тест → принятый навык», без бесконтрольного изменения личности или веса модели из одной реплики.

### 4C. Обучение
- SOUL affect classifier и маленькая последовательная модель поведения (GRU/Transformer light) на качественном мультилингвальном corpus; независимая слепая проверка, человеческая оценка RU/ES, отсутствие манипулятивных реакций.
- LoRA/QLoRA одного **совместимого** LM backbone: диалоговый стиль, объяснения, самопознание архитектуры, следование границам инструментов, reasoning. Квантизация и NVIDIA CUDA код из архивного SOUL GPU V1 не переносится автоматически на AMD DirectML.
- Адаптеры для пяти PersonaID только с изолированными разрешениями, без утечки личных контекстов.
- Использование памяти в inference — без обязательного нового finetune; сначала проверка retrieval. Весовые эксперименты не должны «запомнить» секреты.

### 4D. Приёмка
Четко различает «знал» / «не знал», правильно обновляет изменившиеся факты, не нарушает Persona isolation, демонстрирует измеримый выигрыш на LongMemEval-подобных задачах, не деградирует на baseline; эмоциональная устойчивость оценена отдельно. Разные тесты памяти не смешивать в одно вымышленное число интеллекта.

## 5. Третий этап — CREATOR (приоритет №3, дополнительно <=50 GB)

**Пользовательский результат:** NOX создаёт код, страницы, интеграции, изображения, оригинальные видеосцены, звуковые сообщения и средства своего D02-оформления. По согласованному ночному окну может самостоятельно дописывать модули и создавать тестируемые кандидаты — без права напрямую обойти STOP/SAFE70/permissions.

### 5A. Очерёдность загрузок
1. Переиспользовать Qwen2.5-Coder:7b. Только при победе на исходниках NOX загрузить альтернативный coding candidate. Один coding specialist в памяти GPU только во время работы.
2. Рендер D02 для космических «селфи»/сцен — без дополнительных гигабайт AI весов. Затем одна AMD-проверенная компактная модель image generation/edit с ComfyUI.
3. Video: сначала короткие procedural 2D/3D видео D02 с voice-over; затем испытать один компактный Wan2.2 5B с offload или иной действительно совместимый вариант. «Подходит для 8 ГБ по документации» не равно «работает на RX6650M Windows в этой сборке».
4. Локальные ASR/TTS/voice conversion/lip-sync модели для пяти персонажей, с анализом лицензии, качества и разрешений на использование голоса.
5. Тестовые библиотеки для WPF/WebView2, code agent, git worktree, builds, проверки безопасности; никаких вторых persistent host.

### 5B. Разработка
- Forge autonomous developer: OBSERVE → issue → plan → git worktree patch → static check → tests → evaluate vs parent → approval gate → integrate → rollback candidate.
- D02 self-portraits и видео, timeline, new UI screen with user-validated canonical template, audio reactive core, generated 3D environments.
- Vision/camera/screen/PC control только с согласованными разрешениями, audit trail и индикаторами.
- Personas: раздельные лица/голоса/память, NOX PRIME всегда остаётся не-человекообразным meta-core.
- Resource scheduler: GPU VRAM lease, model unload/load, sleep/resume, priority voice/chat vs media/training, no hidden GPU parallelism.

### 5C. Обучение
- Coding LoRA по лицензированным патчам и проверенным тестами репозиторным задачам; frozen benchmark против исходной coder-модели.
- Отдельные медиа-персонажные адаптеры/consistent-character LoRA только при совместимости GPU и разрешениях; не обещать video diffusion training на 8 GB.
- Обучение tool-use policy на локальных симулированных сценариях, реальные разрешения не выводятся из «owner_verified» текста.
- Отбор удачных разработческих стратегий по архиву экспериментов (Darwin Gödel/AlphaEvolve идеи), не «самокопирующийся червь».

### 5D. Приёмка
Реальный патч + тест + rollback, независимый QA, подпись/BuildID физического Windows EXE по релизным требованиям, один работающий сайт/приложение, честный журнал кода/медиа, оценка на репо-задачах (SWE-bench Pro V2 как дополнительная шкала) и доказательство, что нет удаления функциональности.

## 6. Четвёртый этап — EVOLUTION & MEMORY RESEARCH (приоритет №4, дополнительно <=50 GB)

**Пользовательский результат:** NOX способен месяцами накапливать опыт, повторно использовать подтверждённые навыки, проводить научно организованные эксперименты и улучшать собственные retrieval, эмоциональные классификаторы, код и совместимые LoRA-адаптеры по воспроизводимым метрикам.

### 6A. Очерёдность загрузок
1. Только лицензированные и разрешённые корпуса для обучения embeddings, reranker, памяти, процедурных навыков, hard negatives, временны́х связей, языков RU/ES; не сырые личные переписки без согласия.
2. Небольшие embedding/reranker trainable backbones и validated vector/graph tools; переиспользовать S03/FTS5, не заводить второй authoritative store.
3. Наборы памяти/действий: LongMemEval, LoCoMo, BEAM и DolphinBench при выполнении требований лицензии, plus NOX-specific private held-out challenges.
4. Репозиторные benchmark suites, audit/metrics dashboard, proof-of-learning datasets.
5. Storage только для фактических checkpoint, manifests и rollback последних доказанных моделей, без бесконечного дублирования файлов.

### 6B. Разработка
- Memory learner: разметка знаний с источниками, обновление и опровержение, timeline, repeat/rehearsal, memory confidence, актуальность, перенос подтверждённых навыков.
- Scientific Lab: реестр гипотез, литературы, экспериментов, контрольных групп, отрицательных результатов, воспроизводимость до/после.
- Archival evolution: кандидаты патчей и отдельных совместимых весов, строгие release gates, guard от reward hacking, train/eval leakage.
- Continual improvement scheduler: event driven, GPU safe lease, quiet hours owner opt-in, progress not fake, visible HALT when no meaningful tasks.
- Hierarchical skill adaptation and knowledge transfer without cross-Persona data mixing.

### 6C. Обучение
- Дообучение embeddings/reranker на размеченных retrieval tasks; temporal memory policy, compression, forgetting/replay, outcome-driven skills models.
- Проверка drift и catastrophically forgotten skills; freeze best baseline and compare unknowns.
- Если аппаратного запаса нет, кандидат ждёт CPU/иной GPU; NOX объясняет ресурсную цену и ожидаемое ограничение.
- Сами 200 GB скачанных данных не означают продвижение интеллекта — только реальные изменения на независимом benchmark.

### 6D. Приёмка
Улучшение в нескольких независимых память/код/агентность наборах с отчётом confidence, стабильность RU/ES, source-aware factuality, user-approved experience, no memory leakage, no unauthorized action, reproducible commits/adapters. Компетентность на реальной работе первична.

## 8. Почему это не просто «много моделей»: техническая модель

RESIDENT CORE = always-on service + state + event log + privacy policy + allowed tools + router; PRIMARY LLM = одна прогретая совместимая модель при наличии VRAM; specialized neural backbones и адаптеры = verified artifacts load-on-demand. Эмоциональная подсистема — обучаемый классификатор/поведенческая модель плюс причинно объяснимое состояние, но не «веса чувств»; память в проверяемой S03 и retrieval; навыки в версии с evidence; научные гипотезы проверяются независимыми средствами. GPT/Grok — только опциональные облачные учителя/рецензенты с owner approval, Groq = hosted inference provider, не локальные веса; tensor merge всех 19 разных Ollama моделей запрещён как бессмысленный.

Пример требуемого инициативного сообщения NOX: «Сейчас мои 8 ГБ GPU заняты обучением; видео я могу поставить в очередь. Вариант 1 — сохранить обучение, затем создать ролик. Вариант 2 — переключить вычислительные ресурсы после сохранения checkpoint и твоего подтверждения. Потребность в VRAM выбранной видеомодели пока не измерена — сначала запускаю безопасный тест совместимости». Так выглядит честное функциональное самопонимание.

## 9. Критерии на практике, без имитаций

До/после: latency first-token p50/p95, GPU/CPU processor, VRAM/Hotspot, answer tokens/s, hallucination rate, RU/ES conversational quality, legitimate refusal and privacy, emotion appropriateness, memory across reboots, temporal/contradiction accuracy, skills retention, coding tests, WOW UI fidelity + reduced motion, selfie/video completion, unit and Windows E07 same BuildID. Каждая метрика = указать dataset, version, model SHA, sample size и confidence; не выбирать один красивый процент вместо честной картины.

NOX может служить системным агентом круглосуточно **после настроенного владельцем Windows автозапуска** и допускаемых контролируемых задач. Никаких новых schedules без разрешения. Автоматическое обучение/самопрограммирование возможно как циклы с лимитами/приоритетами и стоп-условиями, не как непрерывное небезопасное расходование GPU.

## 10. Что ChatGPT реально может выполнить, а что нет

ChatGPT с доступным GitHub/Drive/Notion может подготовить и изменять исходники/спеки/тесты/манифесты, сверить source SHA и информацию о моделях, провести тесты в текущей изолированной среде, сохранить канон. Без прямого исполнения на Windows владельца нельзя доказать, что новая политика включена, что модель скачалась, что VRAM хватает или что EXE реально работает. Для владельческого ПК нужен один проверенный установщик/раннер с preflight, подписью/пинами, разрешениями и подтверждением telemetry; вся работа с GPU выполняется там. Существующая ошибка PowerShell ScriptBlock.Create на 7 ноября требует отдельного исправления; не выдавать Git fetch за успешную установку.
